# Issue tracker

Issues and implementation tickets live in GitHub Issues for `teddychan/dragon-kit`.
Use `gh` from the repository checkout. Read the full body, comments, and labels before
changing an existing issue. Check existing issues before creating a duplicate.

Create issues and comments with multiline bodies supplied through `--body-file`.
Every issue or comment produced during triage starts with:

> *This was generated by AI during triage.*

Use one issue per independently verifiable behavior. Record acceptance criteria and
out-of-scope work. Apply one category and one state from
[`triage-labels.md`](triage-labels.md). A maintainer can direct an issue straight to
`ready-for-agent` when its behavior and verification are established.

For dependent tickets, use GitHub's native blocking relationships. If those are
unavailable, record blocking issue numbers in a `Blocked by` section. Independent
tickets have no blocking edges. Do not close or modify a source parent issue while
publishing its child tickets.

**PRs as a request surface: no.** Explicitly named PRs can still be reviewed.

Use `gh issue view` to fetch tickets, `gh issue list` to discover work,
`gh issue create` to publish tickets, and `gh issue edit` to update labels.
Implementation PRs reference the issues they resolve.
