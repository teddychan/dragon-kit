# Domain documentation

This package has one domain context. Read `GLOSSARY.md` at the repository root when
it exists, and relevant decisions under `docs/adr/` before changing a domain contract.
Create these documents when an actual terminology or architecture decision needs
recording. Their absence does not block work.

Use the glossary's terms in tickets, tests, and APIs. Surface conflicts with existing
decisions instead of silently replacing them.

`CONFORMANCE.md` remains normative for adoption and shared UI ownership.
`docs/MAC-APP-RELEASE-LIFECYCLE.md` remains normative for app identity and release
ownership. `docs/CONFORMANCE-INCIDENTS.md` records rationale, and `TechDebt.md` records
sequenced migration work. Dated plans under `docs/superpowers/` are historical evidence,
not implementation instructions. Domain documents do not supersede these authorities.
